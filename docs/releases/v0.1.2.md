# OniLink 0.1.2

OniLink 0.1.2 adds an Xbox-authenticated XUID allowlist at the proxy ingress and makes Pterodactyl runtime updates stable-only, checksum-verified, and self-maintaining.

## Authenticated player access

- OniLink validates the Xbox login chain first, then checks the signed XUID before allocating the player session or contacting BDS.
- The list is stored in `allowlist.properties`; gamertags are operator labels and never authorize a login.
- Admins can add/remove XUIDs from the OniLink console, authorized in-game commands, or **Dashboard → Allowlist**.
- Removing an entry disconnects its live session by default.
- An enabled empty list denies every player. Add your own account before enabling it.

Quick Pterodactyl sequence:

1. Leave **Enable authenticated XUID allowlist** off and join once.
2. Add the connected account in **Dashboard → Allowlist** or run `allowlist add <gamertag>` in the panel console.
3. Confirm with `allowlist list`.
4. Enable the panel switch and restart OniLink.

BDS must remain `online-mode=false` and `allow-list=false`; public access is now decided by OniLink's authenticated ingress.

## Stable automatic updates

On each container start, `start-onilink.sh` queries GitHub's `/releases/latest` endpoint. This follows the newest normal release while excluding drafts and prereleases. It downloads `SHA256SUMS`, `OniLink.jar`, `start-onilink.sh`, and `onilink.properties.example`, verifies all runtime files, and only then replaces changed files.

- Active `config.properties` is preserved.
- Prior JAR, updater, and reference-template files are retained when changed.
- If GitHub or checksum verification fails, the last installed JAR still starts.
- A newly downloaded updater takes over on the following restart.

Existing v0.1.1 containers already discover the normal v0.1.2 JAR on restart. Reimport the v0.1.2 egg once to add the new allowlist panel switch and current install/updater definition; runtime self-update cannot rewrite an egg definition stored by Pterodactyl.

## Upgrade

1. Back up `config.properties`, `dashboard/`, `allowlist.properties` if present, and forwarding key files.
2. Restart OniLink to install the v0.1.2 JAR automatically, or download the verified release bundle manually.
3. Reimport `egg-onilink.json` if the server is panel-managed and you want the new allowlist switch.
4. Add your XUID before enabling enforcement.
5. Restart and test both an allowed and unlisted Xbox account.

No native backend replacement is required solely for the allowlist feature. The v0.1.2 bundle nevertheless includes version-aligned OniBridge and OniBridge-Geyser artifacts.
