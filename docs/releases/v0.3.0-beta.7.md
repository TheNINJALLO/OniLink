# OniLink 0.3.0-beta.7

OniLink `0.3.0-beta.7` is a corrective clock-compensation release for separately hosted OniLink
and OniBridge systems. A live deployment reported a fixed proxy-minus-backend difference of
`9922992 ms`, which exceeded beta 6's five-minute configuration bound and caused OniBridge to fail
closed during startup.

> [!IMPORTANT]
> The BDS 1.26.45.1 profiles remain candidates until the complete real-server startup, proxied
> login, verified XUID, disconnect, command, and shutdown matrix passes. Clock compensation does
> not relax the native profile gate.

## Corrective change

- `forwarding.proxy_clock_offset_ms` now accepts `-86400000..86400000` ms, a maximum fixed
  difference of 24 hours in either direction.
- The live-observed `9922992 ms` case has direct configuration and token-validation regression
  coverage.
- The setting still defaults to `0` and must be explicitly configured on OniBridge.
- Token lifetime, `allowed_clock_skew_ms`, signature verification, replay retention, pending-login
  expiry, and trusted-proxy enforcement are unchanged.

## Upgrade and recovery

1. Replace the beta 6 OniBridge shared library with the exact beta 7 artifact for BDS `1.26.45.1`.
   Do not leave both plugin versions in the Endstone `plugins` directory.
2. Keep `allowed_clock_skew_ms = 2000`.
3. For the deployment that reported the live diagnostic, configure:

   ```toml
   [forwarding]
   allowed_clock_skew_ms = 2000
   proxy_clock_offset_ms = 9922992
   ```

4. Fully restart Endstone, confirm the startup warning reports `9922992 ms`, and retry the proxied
   login.
5. Provider-managed NTP remains the preferred permanent repair. If the measured offset changes,
   update the configured value from a newly authenticated rejection diagnostic rather than
   increasing the general skew window.

Existing forwarding secrets, key IDs, bridge IDs, backend names, player data, worlds, and control
plane accounts do not need migration.
