# OniLink 0.3.0

OniLink `0.3.0` is the stable release of the 0.3 platform. It promotes the complete beta line after
operator acceptance of the deployed Linux path and ships OniLink, OniBridge, the single-container
multi-tenant control plane, per-session cross-version routing, packet operations, and the corrected
Pterodactyl egg as one checked release.

## Production target

The production-approved native path is:

- BDS `1.26.45.1` Linux x86-64;
- Endstone `0.11.10`;
- `onibridge-0.3.0-bds-1.26.45.1-linux-x86_64.so`;
- profile `bds-1.26.45.1-linux-x86_64-8ba803f23d681816`;
- OniForward `[forwarding] protocol = 3`;
- `[compatibility] allow_unreviewed_profile = false`.

The stable manifest reports `production_ready=true` and identifies `linux-x86_64` in
`production_ready_platforms`. The Windows BDS `1.26.45.1` DLL is included for controlled testing,
but remains in `candidate_platforms` until Windows receives its own live acceptance. Do not enable
`allow_unreviewed_profile` on a production Windows backend.

## Highlights

- Negotiates supported 1.26.44/2168, 1.26.45/2169, and 1.26.50/2192 client protocols per session,
  allowing mixed client versions on one running listener without a global mode switch.
- Uses OniForward v3 signed, persisted proxy boot IDs and one-time increasing sequences. Separately
  hosted OniLink and OniBridge systems no longer require synchronized wall clocks or a changing
  `proxy_clock_offset_ms`; keep that value at `0`.
- Adds one shared provider control plane with tenant logins, tenant-scoped proxy listeners,
  isolated backend catalogs, primary-route selection, backend editing/removal, and allowlist import.
- Adds the privacy-aware packet monitor, protocol evidence and translation tooling, OniPacket rules,
  Protocol Lab, and per-player virtualization controls.
- Adds OniFlow, continuity, sentinel, pulse, fleet, connect, pack-analysis, notification, audit, and
  operational dashboard modules with owner-controlled enable/disable state.
- Generates new backends, unique keys, restricted key files, matching OniBridge configuration, and
  a setup ZIP from the dashboard.
- Fixes the Pterodactyl egg's boolean validation, permits a blank default forwarding-secret field
  when named per-backend secret sources are used, and defaults new installations to the `stable`
  automatic update channel.

## Upgrade from 0.3 beta

1. Back up `config.properties`, `dashboard/`, and every backend's OniBridge configuration and key.
2. Replace `OniLink.jar` with the stable artifact, or let the Pterodactyl `stable` channel install it
   after this release is published.
3. Import the stable `egg-onilink.json` if Pterodactyl still rejects saved `true`/`false` feature
   fields. Existing configurations and dashboard data are preserved, but retain your backup.
4. Install the exact stable Linux `.so` above on each BDS `1.26.45.1` + Endstone `0.11.10` backend.
5. Keep `[forwarding] protocol = 3`, `proxy_clock_offset_ms = 0`, and the production profile ID shown
   above. Start the backend before OniLink and complete a proxied join and reconnect test.

Beta 9 and beta 10 use the same OniForward v3 wire protocol, but matching stable component versions
are recommended. When upgrading from beta 8 or older, both the proxy JAR and native bridge must be
updated together.

## Verification and privacy

Verify every downloaded release file with `SHA256SUMS`. BDS itself is not redistributed. Unknown or
mismatched BDS binaries, Endstone versions, profiles, architectures, and hook bytes remain blocked.
The dedicated profile-generation audit acquired and checked the official archives before profile
review and live acceptance. Public release CI verifies that immutable lock/profile/adapter evidence,
then rebuilds and tests both native artifacts without redistributing or repeatedly downloading BDS.

Detailed packet captures may contain chat, XUIDs, player names, network endpoints, decoded fields,
and incoming wire bytes. Authentication tokens and forwarding secrets remain redacted. Restrict
dashboard access and inspect exported captures before sharing them.
