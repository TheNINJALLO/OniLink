# OniLink 0.3.0 Beta 4

OniLink `0.3.0-beta.4` fixes the backend Login identity envelope used when a Minecraft Bedrock
`1.26.50` Preview client on protocol `2192` joins the locked BDS `1.26.44.3` backend on protocol
`2168`. Regular 1.26.44 clients already joined successfully on the same deployment; beta 4
corrects the Preview-specific step that previously stalled before the BDS encryption handshake
and surfaced to the client as Kelp.

This remains a prerelease until the corrected path completes live Preview acceptance. The Linux
BDS `1.26.44.3` + Endstone `0.11.9` OniBridge profile remains production-approved. The Windows
profile remains a candidate requiring the evidence described in
[Compatibility](../COMPATIBILITY.md).

## Fixed

- Build the backend-facing `ThirdPartyName` from the Mojang-authenticated Xbox display name instead
  of relying on an optional, client-controlled Preview skin field.
- Force `ThirdPartyNameOnly=false` before signing the protocol-2168 backend client-data JWT.
- Keep OniForward, backend version, address, and stable backend identity in the same normalized
  Login envelope.
- Show the backend verification warning only when OniForward is actually disabled, rather than
  warning about the intentionally removed legacy verifier.
- Log OniBridge envelope and verification failures with sanitized player/source context. Complete
  OniForward tokens and secret material are never logged.

## Upgrade

1. Back up `config.properties`, `dashboard/`, `cache/`, and `onibridge.toml`.
2. Select the Pterodactyl `beta` update channel, or pin `ONILINK_VERSION=v0.3.0-beta.4`.
3. Restart OniLink to download and verify the beta 4 JAR.
4. Replace the native OniBridge file with the matching beta 4 artifact if you want the new
   backend-side rejection diagnostics, then restart BDS and wait for the exact reviewed-profile
   hook-active message.
5. Keep the backend set to its real version: `backend.<name>.protocol=1.26.44` when automatic UDP
   discovery is unavailable. Do not label the 1.26.44 backend as 1.26.50.
6. Join once with 1.26.44 as a control, then complete the 1.26.50 checklist in
   [Cross-version support](../CROSS_VERSION_1_26_50.md).

No key, bridge ID, backend name, port, or configuration migration is required. The beta-channel
updater preserves the existing configuration and verifies the published checksum before replacing
the runtime JAR.

## Verification

- All 476 OniLink tests and the embedded dashboard production build passed from a clean tree.
- A dedicated regression test covers a protocol-2192 client whose skin JWT omits
  `ThirdPartyName` and verifies the resulting protocol-2168/OniForward envelope.
- The full Windows OniBridge plugin compiled against the pinned Endstone source.
- Both native CTest targets passed.
- The release workflow repeats Java, dashboard, Linux and Windows native, checked-profile,
  packaging, checksum, and Linux `GLIBC_2.35` gates before publishing artifacts.

The release contains no Mojang/Microsoft BDS binary or licensed client file.
