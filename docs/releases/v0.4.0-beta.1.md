# OniLink 0.4.0-beta.1

This beta adds Update Center, independently signed protocol packages and network/player services
for testing with BDS **1.26.45.1** and **Endstone 0.11.10**. Endstone remains required.
The stable release remains v0.3.0. The new maintenance and network workflows need live acceptance
on your test system; automated fixtures do not certify every gameplay or native-runtime behavior.

## What changed

- Owner Update Center: streamed archive verification, compatibility fixtures, release review,
  exact-version acceptance records and deployment history.
- Managed Endstone maintenance: confirmed player evacuation, service stop/start, complete backups,
  version/health checks, confirmed returns, snapshot rollback and manual recovery.
- Signed protocol packages: Ed25519 publisher verification, dependency checks, changed-route fixture
  requirements and activation/rollback for new connections. Existing connections keep their registry.
- Player services: parties, friends, chat, server menus, group queues and reserved slots.
- Resource-pack releases with dependency validation, staged activation and rollback.
- Addon API 1, lifecycle events, dependency ordering, a project generator and an executable contract.
- Authenticated multi-node presence, moderation, routing and capacity coordination.
- OniPulse sampled translation metrics and OTLP export, bounded workers and a smaller initial
  dashboard bundle.
- BDS acquisition and protocol improvements: offline server-set verification, pinned import locks,
  hotfix-aware codec diffs and stricter 1.26.45 translation fixtures.

## Download and test

1. Stop the test proxy and back up its configuration, plugins and entire data directory. Back up
   managed Endstone directories separately before enabling maintenance actions.
2. Download `OniLink.jar` and `SHA256SUMS` from this release and verify the checksum. Replace the
   test proxy's existing JAR, preserving its configuration and data. Java 21 is required.
3. If updating OniBridge, use the matching `onibridge-0.4.0-beta.1-bds-1.26.45.1-<platform>` artifact
   from this release and restart Endstone. Keep the existing OniForward secrets and protocol 3
   configuration. The native target remains exact BDS 1.26.45.1 + Endstone 0.11.10; Windows remains
   a candidate pending its own live acceptance.
4. On Pterodactyl, set the version to `v0.4.0-beta.1`, or select the `beta` update channel, then
   restart. A version pin is preferable when reproducing test results. The egg's default stays stable.
5. Confirm the dashboard reports version `0.4.0-beta.1`, then log in as the provider owner and open
   **Update Center**. Existing configuration is preserved. New configuration keys are documented
   in the included `onilink.properties.example`; merge the keys you need into your existing file.
6. Follow the [Update Center guide](https://github.com/TheNINJALLO/OniLink/blob/v0.4.0-beta.1/docs/UPDATE_CENTER.md)
   for the operator-owned service commands, limbo backend, publisher keys and optional node/metrics
   configuration. Enable Connect for player services and Continuity for maintenance. Uploads stage
   files; they do not start a server or activate code by themselves.

The existing 0.3.0 OniBridge is wire-compatible with this proxy's OniForward v3. Matching beta
artifacts are supplied for testing both components together. BDS server archives are not redistributed.
Protocol fixes can ship independently, while future native updates still need Endstone compatibility.

## Validation

Before tagging, local checks passed 520 Java tests, 41 dashboard tests, 88 Python tests and two
Windows native tests, plus the generated addon lifecycle contract. Three Python checks are expected
Windows platform skips. Frontend lint/type/format checks passed, and both supplied 1.26.45.1 server
archives passed inspection. GitHub rebuilds the tagged Java and native artifacts, runs the release
checks, enforces the Linux GLIBC 2.35 policy and publishes checksums with the downloads.

To return to stable, stop the test instance and restore its pre-beta files and data backup with
v0.3.0. Restoring only an older JAR does not undo activated packages, pack releases or maintenance
changes to a managed server.
