# OniLink 0.3.0 Beta 2

OniLink `0.3.0-beta.2` makes day-to-day backend and allowlist management available directly in the
provider and tenant dashboards. It builds on the first 0.3 operations beta without changing the
exact native BDS compatibility profile.

This is a prerelease. The Linux BDS `1.26.44.3` + Endstone `0.11.9` OniForward profile remains
production-approved. The Windows profile remains a candidate requiring the evidence described in
[Compatibility](../COMPATIBILITY.md).

## Highlights

- Edit an existing backend destination without rebuilding the complete configuration.
- Select the primary backend that receives new players from the provider or tenant dashboard.
- Remove a backend safely by choosing a replacement route first. OniLink repairs fallback, forced
  host, join, limbo, quarantine, control, and Protocol Lab references before accepting the change.
- Prevent deletion of the final backend and validate the complete configuration before every
  write.
- Preserve removed-backend key files for recovery instead of deleting secrets automatically.
- Import XUID allowlists from bounded JSON, CSV, TSV, properties, or numeric text files.
- Choose atomic merge or replace behavior, with rejected-row details and explicit protection
  against insecure name-only entries.
- Restart tenant proxy runtimes automatically after scoped backend edits; provider configuration
  changes clearly identify when a service restart is required.

## Upgrade

1. Back up `config.properties`, `dashboard/`, `cache/`, and the matching OniBridge configuration.
2. Set the Pterodactyl update channel to `beta`, or pin `ONILINK_VERSION=v0.3.0-beta.2`.
3. Restart OniLink and verify the downloaded files with `SHA256SUMS`.
4. Compare `config.properties` with `onilink.properties.example`; upgrades preserve the live
   configuration.
5. Open **Backends** to verify the primary route before editing or removing an existing backend.
6. Install the matching `onibridge-0.3.0-beta.2-bds-1.26.44.3-linux-x86_64.so` only on the exact
   approved BDS/Endstone target.

The beta-channel updater checks published prereleases at every container start, verifies release
checksums, replaces runtime files atomically, preserves the live configuration, and keeps the last
JAR for rollback. Use `pinned` to hold this exact build.

## Allowlist import safety

Imports accept at most 128 KiB and 5,000 unique XUIDs. Replace mode rejects the complete import if
any row is invalid, so a malformed file cannot partially erase an existing allowlist. Player names
may be stored as labels, but every authorization entry must include a numeric XUID.

## Verification and limitations

The source release is gated by the complete Java, dashboard, Python packaging/egg/ABI, and native
core suites. Linux artifact CI also enforces the `GLIBC_2.35` ceiling and rejects mixed
`libstdc++`/`__cxx11` symbols.

This beta uses the repository's checked BDS lock, paired profiles, generated adapter bindings,
review state, and runtime evidence. The exception applies only to prereleases. Stable releases
still require fresh official BDS archive and executable validation.

No Mojang/Microsoft BDS binary or licensed client file is included.
