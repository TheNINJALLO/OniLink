# OniLink 0.3.0-beta.6

OniLink `0.3.0-beta.6` adds a bounded clock-domain translation for deployments where OniLink and
OniBridge run on separate providers and one host clock cannot be repaired. It retains the beta 5
BDS `1.26.45.1`, Endstone `0.11.10`, protocol `2169`, and `1.26.50` preview compatibility work.

> [!IMPORTANT]
> The BDS 1.26.45.1 profiles remain candidates until the complete real-server startup, proxied
> login, verified XUID, disconnect, command, and shutdown matrix passes. Clock compensation does
> not relax the native profile gate.

## Clock-domain compensation

- Rejection messages now report the signed `proxy-minus-backend` clock offset after the token's
  HMAC, player, bridge, backend, and lifetime claims have passed.
- New OniBridge setting `forwarding.proxy_clock_offset_ms` accepts `-300000..300000` ms and defaults
  to `0`.
- Positive values mean the OniLink host clock is ahead; negative values mean it is behind.
- Validation compares the token against the translated backend clock while keeping the normal
  `allowed_clock_skew_ms` tolerance unchanged.
- Replay-cache and pending-login expirations are translated back to backend time, so compensation
  does not enlarge the five-second token lifetime or create a longer replay window.
- `onibridge status` reports the active offset and normal skew, and OniBridge warns at startup when
  compensation is non-zero.

## Upgrade and recovery

1. Install the beta 6 OniLink JAR and the exact beta 6 OniBridge artifact for BDS `1.26.45.1`.
2. Keep `allowed_clock_skew_ms = 2000` and add `proxy_clock_offset_ms = 0` under `[forwarding]`.
3. Restart OniBridge and attempt one proxied login.
4. If the login is rejected for time, copy the reported signed offset into
   `proxy_clock_offset_ms`, save, and fully restart OniBridge.
5. Retry the join and complete the live acceptance checklist. Provider-managed NTP remains the
   preferred permanent repair.

Existing forwarding secrets, key IDs, bridge IDs, backend names, player data, worlds, and control
plane accounts do not need migration.
