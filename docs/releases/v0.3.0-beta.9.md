# OniLink 0.3.0-beta.9

OniLink `0.3.0-beta.9` removes the cross-provider clock dependency from OniForward. The proxy and
BDS host may have different or changing wall clocks; operators no longer copy a new clock offset
after every rejected join.

> [!IMPORTANT]
> Update both components. The v3 token issuer is in `OniLink.jar`, and the v3 verifier plus replay
> state is in the matching profile-specific OniBridge plugin. Updating only one side leaves the
> deployment in migration compatibility mode or unable to use the fix.

## What changed

- OniForward v3 signs a persisted, monotonically ordered per-process proxy boot UUID and a strictly
  increasing one-time sequence into every backend Login.
- OniBridge persists the accepted sequence floor and retired proxy boot IDs in
  `plugins/onibridge/oniforward-sequences.state`.
- Replays, sequences outside the bounded reordering window, retired proxy processes, and v2
  downgrade under a protocol-3 policy fail closed.
- Concurrent logins may arrive out of order within the protected window.
- The persisted state survives a BDS restart and contains no secret, token, player data, XUID, or
  address.
- OniLink stores its boot epoch in `dashboard/oniforward-proxy.state` by default, advances it even
  if the provider clock moves backward, and rejects startup if that safety state cannot be saved.
- Dashboard backend setup and tenant handoff bundles now generate `protocol = 3` automatically.

Wall-clock timestamps remain signed to validate the declared lifetime shape, but v3 never compares
the proxy host's time with the backend host's time. `proxy_clock_offset_ms` is ignored by v3 and
remains only for v2 rollback compatibility.

## Upgrade

1. Stop OniLink and every affected BDS backend.
2. Replace `OniLink.jar` with the beta 9 artifact.
3. Replace OniBridge with the beta 9 artifact built for the backend's exact BDS, Endstone, OS, and
   architecture. Do not rename an old beta 8 file to look current.
4. Edit the live backend file at `plugins/onibridge/onibridge.toml`:

   ```toml
   [forwarding]
   protocol = 3
   allowed_clock_skew_ms = 2000
   proxy_clock_offset_ms = 0
   ```

5. Keep the existing key ID, secret, bridge ID, backend name, trusted proxy CIDR, world, and player
   data unchanged.
6. Start BDS, then start OniLink.
7. Confirm the BDS console reports `OniForward v3 clock-independent verification is active`.
8. Join once and confirm `plugins/onibridge/oniforward-sequences.state` appears automatically.

No permission command is required for either state file. Each process creates and owns its file. Do
not manually edit, copy between unrelated instances, or delete either file during ordinary
operation.

## Rollback

If an emergency rollback is required, set `protocol = 2` before installing the earlier OniBridge
plugin. Protocol 2 is clock-based and can reproduce the original `issued in the future`/`expired`
failure on separate providers. Keep the beta 9 sequence-state file for a later upgrade.

The BDS 1.26.45.1 profiles remain candidates until the complete real-server startup, proxied login,
verified XUID, disconnect, command, and shutdown matrix passes. This forwarding correction does not
relax the native profile gate.
