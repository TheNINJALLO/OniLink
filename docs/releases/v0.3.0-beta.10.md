# OniLink 0.3.0-beta.10

OniLink `0.3.0-beta.10` is a Pterodactyl compatibility hotfix on top of beta 9. It fixes the egg
validation error that prevented an existing OniLink server from saving updated startup settings.
It retains OniForward v3 clock-independent authentication and the BDS `1.26.45.1` / Endstone
`0.11.10` runtime profile introduced in beta 9.

## What changed

- All eight egg enable/disable fields validate their literal `true` or `false` values directly.
  These are the same values OniLink writes to and reads from `config.properties`.
- The admin-only `ONIBRIDGE_FORWARDING_SECRET` field may be blank while assigning the egg when every
  configured backend uses a separate named variable such as `ONIBRIDGE_SURVIVAL_SECRET`.
- A missing secret is not treated as unauthenticated access. Login forwarding still fails closed if
  the environment variable selected in a backend configuration is empty or unavailable.
- The egg embeds no secret values and keeps all secret variables hidden and non-user-editable.

## Upgrade an existing Pterodactyl server

1. Back up the OniLink server files and dashboard data.
2. Import the beta 10 `egg-onilink.json` into the provider's OniLink nest and assign that egg to the
   existing OniLink server.
3. Keep **Enable operations dashboard** set to `true`. Leave the other optional feature switches at
   `false` unless they were deliberately configured.
4. If the active backend references `ONIBRIDGE_FORWARDING_SECRET`, restore the existing shared
   Base64 secret in that admin-only variable. If every backend references its own named variable,
   the default field may remain blank. Never paste a secret into chat, a ticket, or the exported egg.
5. Select the `beta` update channel, or pin `v0.3.0-beta.10`, save the startup settings, and restart
   OniLink.
6. Confirm the dashboard reports `Online · 0.3.0-beta.10` before testing a player login.

The matching beta 10 OniBridge artifacts contain the same v3 authentication correction. When
upgrading from beta 8 or older, update both `OniLink.jar` and the exact profile-specific OniBridge
plugin and keep `[forwarding] protocol = 3`. When upgrading from beta 9 solely for this egg fix, the
beta 9 bridge remains wire-compatible, although matching component versions are recommended.
