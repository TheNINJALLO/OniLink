# OniLink 0.2.0 Beta 1

OniLink `0.2.0-beta.1` introduces a live packet compatibility workspace inside the existing control
plane. It uses the actual incoming relay path to show which packets already map safely through the
compiled client and backend codecs, which packets use reviewed translators, and which definitions
still require protocol research.

This is a prerelease intended for real cross-version testing. OniLink does not infer field semantics
from production traffic or apply numeric-ID guesses.

## Packet monitor

- Every provider and tenant proxy runtime has its own bounded, in-memory monitor.
- The live table records packet model, direction, source/target protocol and packet IDs, relay
  action, match status, player display name, backend label, and time.
- High-volume movement records are sampled one in 20 while aggregate counts continue to update.
- A compiled protocol catalog compares every source packet model with the selected target codec and
  shows how many times each model was seen on the live route.
- Direction, match-result, text, record-limit, client-protocol, and backend-protocol filters turn
  real traffic into a focused compatibility report.
- The JSON export and redacted support bundle include the same safe metadata for maintainers.

## Cross-version assistance

When a decoded packet class exists in both compiled codecs, OniLink marks it **Auto matched**. The
target codec supplies its own packet ID and serializer, so unchanged shared models cross adjacent
versions without a handwritten numeric-ID table. The monitor records the real relay result, not a
prediction.

Reviewed version translators are shown separately as **Translated**. A packet absent from the
target codec becomes **Review required**, and an undecodable packet becomes **Unknown packet**. If a
missing packet shares a numeric ID with another target definition, that class is shown only as an
ID-only research candidate. It is never applied automatically.

The complete workflow, result definitions, test matrix, export handling, and limitations are in
[Packet monitor and cross-version matching](../PACKET_MONITOR.md).

## Privacy and tenancy

- At most 5,000 recent records are retained per proxy, and all records disappear on restart.
- Payloads, chat contents, login chains, forwarding tokens, XUIDs, network addresses, and raw wire
  bytes are never stored by the monitor.
- Reports can contain player display names and backend labels and must be inspected before sharing.
- Existing dashboard authorization resolves tenant packet requests through the assigned runtime;
  cross-tenant requests are rejected server-side.

## Beta update channel

The Pterodactyl updater now supports three explicit channels:

| Channel | Result on container start |
| --- | --- |
| `stable` | Newest normal GitHub release; prereleases are ignored. |
| `beta` | Newest published release including prereleases. This beta egg's default. |
| `pinned` | Exact public tag configured in `ONILINK_VERSION`. |

Existing eggs do not have `ONILINK_UPDATE_CHANNEL` and continue to default to `stable`. Reimport the
beta egg to receive the selector, verify `ONILINK_VERSION=v0.2.0-beta.1` and
`ONILINK_UPDATE_CHANNEL=beta`, then reinstall or update the JAR from this release. Later reboots will
verify checksums and follow newer beta builds. Select `pinned` to remain on this exact beta.

## Native compatibility

The packet monitor does not change OniBridge's fail-closed compatibility policy. The included Linux
native artifact remains production-approved only for the exact BDS `1.26.44.3` executable and
Endstone `0.11.9`, with the existing `GLIBC_2.35` maximum import. Windows and Geyser retain their
separate candidate/live-test status.

## Upgrade from v0.1.7

1. Back up `config.properties`, `dashboard/`, `allowlist.properties`, and forwarding key files.
2. Download the prerelease and verify the entire directory with `SHA256SUMS`.
3. For Pterodactyl, reimport `egg-onilink.json` so the panel receives **Automatic update channel**.
4. Set the channel to `beta`; use `pinned` instead if you do not want later betas on reboot.
5. Restart, sign in to the normal dashboard, and open **Packet Monitor**.
6. Exercise the cross-version behavior, export a report, and report incorrect results with the
   exact two protocol numbers and player action. Do not attach secrets or raw authentication data.

No configuration, tenant, proxy, backend, key, or allowlist migration is required.

```bash
cd onilink-release

```
