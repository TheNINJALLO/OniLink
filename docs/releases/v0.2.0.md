# OniLink 0.2.0

OniLink `0.2.0` is the stable promotion of the tested Beta 2 system. It ships the standalone Java 21
Bedrock edge, embedded control plane, packet monitor, tenant hosting, guided backend onboarding,
self-updating Pterodactyl egg, and production-approved native Linux OniBridge profile.

## Supported runtime family

The stable runtime family is now intentionally limited to two components:

- **OniLink** authenticates clients, routes sessions, signs `OniForward` claims, and serves the
  operations dashboard.
- **OniBridge** verifies each claim and restores the authenticated XUID before BDS chooses native
  player storage.

Support for Java-backed routes has been removed. The former extension, build jobs, release artifact,
secret variable, compatibility switch, mixed deployment example, and operator documentation are no
longer shipped. Existing operators using that experimental path must remove it before upgrading;
`v0.2.0` supports native BDS/Endstone backends only.

## Stable features

- Detailed, operator-controlled packet capture with decoded source/translated fields, token
  redaction, bounded memory, filtered JSON export, and metadata-only support bundles.
- Cross-version codec observation and review queues driven by incoming traffic without guessing
  packet semantics.
- Authenticated operations dashboard with roles, TOTP, audit records, allowlist management, health,
  transfers, logs, alerts, metrics, and safe configuration editing.
- Owner-managed tenant accounts and isolated proxy listeners inside the same OniLink container and
  dashboard.
- Guided **Add Backend** setup that creates matching route properties, a unique secret, native TOML,
  restricted key file, and installable setup ZIP.
- Stable/beta/pinned Pterodactyl update channels with checksum verification, atomic replacement,
  preserved live configuration, and rollback files.

## Native compatibility

The Linux plugin is production-approved only for the exact BDS `1.26.44.3` executable, Endstone
`0.11.9`, and profile ID `bds-1.26.44.3-linux-x86_64-06effdd00067f1ae`. Its release build is capped
at `GLIBC_2.35` and rejects mixed `libstdc++`/`libc++` ABI contamination. Windows remains a candidate
until its live client/storage matrix is completed.

## Upgrade

1. Back up `config.properties`, `dashboard/`, `allowlist.properties`, native configuration, and key
   files.
2. Download `v0.2.0` and verify the directory with `SHA256SUMS`.
3. Remove any configuration and deployment files for the discontinued Java-backend path.
4. Pterodactyl users should reimport `egg-onilink.json`, confirm
   `ONILINK_UPDATE_CHANNEL=stable`, and run **Reinstall Server** once if upgrading an egg without the
   channel-aware updater.
5. Compare `config.properties` with `onilink.properties.example`, restart BDS first, then OniLink.
6. Verify join/leave/rejoin storage, direct-join rejection, commands, switching, allowlist, dashboard,
   packet monitoring, and tenant routes used by the deployment.

No migration is required for native backend identity, tenant accounts, allowlist entries, dashboard
accounts, or BDS player data.
