# OniLink 0.1.0 Candidate 2

Candidate 2 makes adding native BDS servers a guided operation. It also removes the common Pterodactyl key-permission failure by securing the selected Linux key file before OniBridge reads it.

## Highlights

### Guided BDS backend setup

The authenticated dashboard now includes **Configuration → Add BDS Backend**. An admin or owner enters the route name, private BDS endpoint, trusted proxy CIDR, bridge ID, and key ID once. OniLink then:

- preserves existing routes and appends the new backend;
- generates a unique standard-Base64 secret from 32 random bytes;
- installs OniLink's copy as `secrets/<backend>.key` with owner-only permissions;
- validates the complete configuration and creates a backup;
- returns the matching key and complete `onibridge.toml` for Endstone.

The generated key is shown once and is never written into `config.properties` or the dashboard audit log. Adding the route does not silently change the hub, initial join order, or failover policy.

### Safer Pterodactyl secret files

Native OniBridge now rejects non-regular files and symlinks, then restricts a selected Linux key file to owner read/write (`0600`) before reading it. This lets a key uploaded through Pterodactyl work without editing the Endstone egg's startup variables. A filesystem that cannot enforce the permission change still fails closed.

### Operator documentation

The new [Adding another BDS backend](https://github.com/TheNINJALLO/OniLink/blob/main/docs/ADDING_BACKEND.md) guide includes:

- a field-by-field dashboard walkthrough;
- exact OniLink and Endstone Pterodactyl paths;
- complete proxy and TOML examples;
- hub, join-order, and failover choices;
- manual setup when the dashboard is unavailable;
- troubleshooting and safe removal steps.

The GitHub Wiki contains the matching task-oriented **Adding Backends** page.

## Upgrade from Candidate 1

1. Stop BDS/Endstone.
2. Remove the generated `plugins/.local/onibridge-*.so` shadow copy if Endstone left one behind.
3. Replace the native plugin with `onibridge-0.1.0-bds-1.26.44.3-linux-x86_64.so` from this release.
4. Verify its SHA-256:

   ```text
   50616831e9d676bf03efcc185b20a41320e1bc39db77236c4b3cede3528a0664
   ```

5. Start BDS and confirm `OniBridge native identity hook is active for the exact reviewed profile.`
6. Restart OniLink. Existing Pterodactyl installations using `start-onilink.sh` obtain the new JAR automatically after this release is published and checksum-verified.

Existing routes and secrets do not need to be regenerated.

Verify the downloaded directory before installation:

```bash
sha256sum -c SHA256SUMS
```

## Candidate status

This remains a prerelease. The machine-readable manifest intentionally reports `production_ready=false` until the exact native hook profile has a formal human review and the complete live acceptance matrix is recorded. The operator has reported a working Linux deployment, but that report does not replace the repository's documented promotion gates.

No Mojang/Microsoft BDS binary is included. Supply your own accepted-license BDS `1.26.44.3` installation and Endstone `0.11.9`.
