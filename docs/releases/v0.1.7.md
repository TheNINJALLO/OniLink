# OniLink 0.1.7

OniLink 0.1.7 makes tenant and backend onboarding understandable without requiring proxy,
Pterodactyl, or network-administration experience. Every setup path now clearly distinguishes the
address players join from the separate game server address OniLink forwards them to. The forwarding
protocol and production-approved native compatibility profile are unchanged.

## Clear connection setup

- Tenant proxy creation now presents two numbered sections: **Proxy address players will join** and
  **Game server OniLink will forward players to**.
- Public proxy IP/domain, assigned proxy UDP port, destination server IP/domain, and destination
  server UDP port are four separate fields with realistic examples and plain-language explanations.
- A live `Players connect to this proxy -> OniLink forwards them to this server` preview shows the
  complete route before it is submitted.
- The proxy-source security field explains that it is the proxy IP observed by the destination
  server and must not contain a port.
- Tenant proxy creation automatically copies the public proxy IP into the source-IP field while
  still allowing operators to replace it when NAT or container networking exposes another address.

## Tenant and backend workflows

- Tenant account fields now distinguish the internal tenant ID, readable customer/network name,
  customer dashboard username, and temporary password.
- The main **Add Backend** wizard splits the destination BDS address into server and UDP-port fields,
  shows the existing OniLink player port automatically, and explains that no new proxy allocation
  is required.
- **My Proxies** keeps the selected player-facing proxy address visible while a tenant adds another
  destination server and pre-fills its trusted source IP from the proxy configuration.
- Proxy tables use **Players connect to** and **Forwards to** headings instead of allocation/backend
  terminology.
- Tenant proxy addresses no longer display their already-included UDP port a second time.

## Validation

- Endpoint formatting handles IPv4, DNS names, bracketed IPv6, and bare IPv6 without producing
  partial or ambiguous addresses.
- Frontend coverage verifies the separated fields and exact API payload for tenant creation, tenant
  proxy allocation, provider backend setup, and tenant backend setup.
- The dashboard suite now contains 29 tests across four files, in addition to the existing Java,
  Geyser, native, Python packaging, Pterodactyl egg, formatting, and ABI gates.
- Linux packaging continues to enforce the `GLIBC_2.35` ceiling and the production-approved exact
  BDS `1.26.44.3` + Endstone `0.11.9` profile.

## Upgrade from v0.1.6

1. Back up `config.properties`, `dashboard/`, `allowlist.properties`, and forwarding key files.
2. Restart OniLink. An updater-enabled Pterodactyl server discovers v0.1.7, verifies
   `SHA256SUMS`, and atomically replaces the runtime files while preserving configuration and data.
3. Reimport the v0.1.7 egg if you want its current bootstrap default. Runtime updates do not rewrite
   an egg definition already stored by Pterodactyl.
4. Open **Tenant Hosting**, **Add Backend**, or **My Proxies** to use the new connection forms. No
   existing tenant, proxy, backend, key, or allowlist migration is required.
