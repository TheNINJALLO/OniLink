# OniLink 0.1.6

OniLink 0.1.6 replaces the legacy embedded dashboard with a responsive React control plane and
moves commercial tenancy into isolated proxy listeners inside the existing OniLink process. The
locked BDS version, Endstone version, OniForward protocol, and production-approved Linux native
profile are unchanged.

## Responsive control plane

- The dashboard is now a typed React application built with Vite and embedded as hashed production
  assets inside `OniLink.jar`; there is still no separate web service or frontend package to deploy.
- Desktop and mobile navigation expose only the pages available to the signed-in role.
- Overview, players, backends, allowlist, guided backend setup, configuration, operations, audit,
  account security, and tenant workflows use consistent tables, forms, dialogs, status states, and
  error handling.
- Player transfer, tracing, disconnect, broadcast, configuration rollback, support-bundle download,
  shutdown, password, TOTP, and account-management actions remain connected to the established
  authenticated dashboard API.
- First-owner setup, sign-in, session expiry, login throttling, and failure recovery are handled in
  the same responsive application.

## Single-container tenant hosting

- The former Pterodactyl Application API provisioner and `tenantctl` release utility are retired.
- Owners create tenant-scoped logins and multiple isolated Bedrock proxy listeners from **Tenant
  Hosting** in the one existing control plane.
- Every logical proxy receives its own UDP allocation, runtime configuration, forwarding keys,
  allowlist, caches, resource-pack directory, backend routes, and player registry while sharing the
  existing container, JVM, update process, and dashboard URL.
- Tenant users land on **My Proxies** and can manage only their assigned listeners, players,
  allowlists, backends, broadcasts, lifecycle actions, and private handoffs.
- Server-side authorization rejects cross-tenant access even when a request bypasses the browser.
- Suspension, enabled state, allocation-conflict checks, and tenant metadata persist across OniLink
  restarts.

## Build and verification

- Gradle now builds the React application before assembling `OniLink.jar` and embeds only the Vite
  production output under `dashboard/`.
- CI installs dependencies from the lockfile and enforces frontend formatting, linting, type
  checks, component tests, and a production build.
- The release candidate passed 24 frontend tests and 414 Java tests locally, including first-owner
  setup, authentication, role-aware navigation, player actions, tenant creation, backend handoff,
  allowlist, configuration, operations, persistence, and cross-tenant authorization coverage.
- Linux packaging continues to enforce the `GLIBC_2.35` ceiling and the production-approved exact
  BDS `1.26.44.3` + Endstone `0.11.9` profile.

## Upgrade from v0.1.5

1. Back up `config.properties`, `dashboard/`, `allowlist.properties`, and forwarding key files.
2. Restart OniLink. An updater-enabled Pterodactyl server discovers the newest stable release,
   verifies `SHA256SUMS`, and atomically replaces the runtime files while preserving live data.
3. Reimport the v0.1.6 egg if you want the current bootstrap default. Runtime updates do not rewrite
   an egg definition already stored by Pterodactyl.
4. Sign in as the owner and open **Tenant Hosting**. Assign one additional UDP allocation to the
   existing OniLink server for each customer proxy; tenants use the same dashboard URL.
5. If the retired v0.1.5 Application API provisioner was configured, revoke its Pterodactyl API key.
   The new single-container tenancy system does not read `dashboard/hosting/` or migrate those
   separate servers automatically.

Existing provider backends, forwarding keys, allowlists, dashboard accounts, and the reviewed
native compatibility profile remain valid.
