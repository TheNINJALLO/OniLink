# OniLink 0.1.0 Candidate 3

Candidate 3 fixes two asynchronous form-reset errors in the embedded operations dashboard. It contains the complete Candidate 2 backend wizard, automatic Linux key hardening, and operator documentation unchanged.

## Fixed

- **Broadcast message:** a successful network broadcast no longer ends with `Cannot read properties of null (reading 'reset')` in the browser.
- **Create dashboard account:** the same failure pattern is fixed before it can affect owner account creation.

The handlers now retain their form element and submitted data before awaiting the API response. A dashboard asset regression test prevents asynchronous handlers from returning to `event.currentTarget.reset()`.

The broadcast itself was reaching OniLink before the browser error; this release fixes the control-plane result handling and clears the form normally after success.

## Upgrade

Existing Pterodactyl installations using `start-onilink.sh` automatically download the corrected `OniLink.jar` after this release is published and checksum-verified. Restart the OniLink container once, then refresh the dashboard page.

No BDS restart, key regeneration, configuration change, or native `.so` replacement is required when upgrading from Candidate 2.
