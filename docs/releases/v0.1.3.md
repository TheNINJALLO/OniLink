# OniLink 0.1.3

OniLink 0.1.3 makes secure multi-backend setup a first-class control-plane workflow. An administrator can now add a native BDS + Endstone backend, generate its isolated key, and receive both matched configurations without searching inside the raw editor.

## First-class backend onboarding

- **Add Backend** has its own main-navigation entry and is linked directly from **Backends** and **Configuration**.
- A three-stage setup view explains which BDS endpoint and trusted OniLink source CIDR to enter.
- The wizard still validates the complete proxy configuration, rejects stale revisions and duplicate routes, writes a rollback backup, and preserves hub/join/failover policy.
- OniLink generates one random 32-byte key per backend and installs its proxy-side copy at `secrets/<backend>.key` with owner-only permissions.
- The result shows the exact non-secret proxy properties already saved, the one-time key, and a complete production-locked `onibridge.toml`.
- Exact Pterodactyl upload paths, backend-first restart order, hook confirmation, and `/server <backend>` test command are shown beside the downloads.
- The generation button is locked while the request is in progress to prevent accidental duplicate submissions.

No forwarding secret is written into `config.properties`, returned in the proxy-properties snippet, or placed in the dashboard audit record. The Endstone configuration uses `active_secret_file`; operators do not need to create a new startup variable for each generated backend.

## Upgrade

1. Back up `config.properties`, `dashboard/`, `allowlist.properties` if present, and forwarding key files.
2. Restart OniLink. The stable updater downloads and verifies the v0.1.3 JAR while preserving the active configuration and keys.
3. Sign in as an admin or owner and open **Add Backend**.

No egg reimport or native plugin replacement is required solely for this dashboard change. New installations should use the v0.1.3 egg and version-aligned artifacts.
